# AcousticVision

**AcousticVision** — настольное приложение для предварительной оценки акустических характеристик речи в помещениях.

Программа позволяет описать помещение, назначить материал и фактуру его поверхностям, задать источник и приёмник звука, сформировать тестовую модель и выполнить расчёт акустических показателей. Основной расчёт строится вокруг времени реверберации **RT60**. Дополнительно учитываются расстояние между источником и приёмником, ослабление прямого сигнала и артикуляция источника.

## Назначение проекта

Проект разработан как прототип программной системы для магистерской работы по анализу акустических характеристик речи в помещениях. Приложение не выполняет полноценное физическое моделирование звукового поля, трассировку лучей или расчёт STI. Оно предназначено для предварительной оценки акустических условий на основе упрощённой модели помещения и статистических формул комнатной акустики.

Основной сценарий работы:

1. Создать или выбрать помещение.
2. Заполнить справочники материалов и фактур.
3. Назначить материал и фактуру поверхностям помещения.
4. Создать источник и приёмник звука.
5. Сформировать тестовую модель с координатами источника и приёмника.
6. Запустить анализ.
7. Получить численные результаты, визуализацию и текстовую рекомендацию.

## Основные возможности

- управление помещениями;

## Архитектура

Проект реализован по подходу **MVVM**.

Общая схема работы приложения:

```text
Пользователь
    ↓
Avalonia Views
    ↓
ViewModels
    ↓
Services
    ↓
AppDbContext
    ↓
SQLite database
```

Основная логика разделена следующим образом:

- `Views` отвечают за отображение интерфейса;
- `ViewModels` хранят состояние экранов и команды пользователя;
- `Services` выполняют работу с данными и расчётами;
- `Models` описывают сущности предметной области;
- `AppDbContext` отвечает за доступ к SQLite;
- `Common` содержит вспомогательную логику: координаты, типы помещений, расчётные коэффициенты, цвета поверхностей.

## Модель данных

В приложении используются следующие основные сущности:

| Сущность | Назначение |
|---|---|
| `RoomModel` | помещение с типом и геометрическими размерами |
| `RoomSurface` | поверхность помещения: пол, потолок или одна из стен |
| `Material` | материал поверхности и его коэффициент звукопоглощения |
| `Texture` | фактура поверхности и её корректирующий коэффициент |
| `SoundSource` | источник звука: название, уровень сигнала, артикуляция |
| `SoundReceiver` | приёмник звука |
| `TestModel` | расчётная конфигурация: помещение, источник, приёмник, координаты и метод анализа |
| `AnalysisResult` | результат расчёта |

Координаты источника и приёмника хранятся не в справочниках источников и приёмников, а в `TestModel`. Это позволяет использовать один и тот же источник или приёмник в разных помещениях и разных положениях.

## Поверхности помещения

В текущей версии используется упрощённое описание помещения. Для каждого помещения задаются шесть фиксированных поверхностей:

- `floor` — пол;
- `ceiling` — потолок;
- `north` — северная стена;
- `south` — южная стена;
- `east` — восточная стена;
- `west` — западная стена.

Площадь поверхности рассчитывается автоматически из размеров помещения. Пользователь выбирает только материал и фактуру.

## Расчёт эффективного звукопоглощения

Для поверхности используется эффективный коэффициент звукопоглощения:

```text
alpha_eff = Clamp(alpha_material + 0.3 * alpha_texture, 0, 1)
```

где:

- `alpha_material` — коэффициент звукопоглощения материала;
- `alpha_texture` — коэффициент фактуры;
- `0.3` — вес влияния фактуры;
- `Clamp(..., 0, 1)` — ограничение значения диапазоном от 0 до 1.

Фактура не заменяет материал, а только корректирует его акустические свойства.

## Расчёт RT60

В программе реализованы две формулы расчёта времени реверберации.

Формула Сабина:

```text
RT60 = 0.161 * V / A
```

где:

- `V` — объём помещения;
- `A` — эквивалентное звукопоглощение.

Формула Эйринга:

```text
RT60 = 0.161 * V / (-S * ln(1 - alpha_avg))
```

где:

- `S` — суммарная площадь поверхностей;
- `alpha_avg` — средний коэффициент звукопоглощения помещения.

В автоматическом режиме формула выбирается по среднему коэффициенту звукопоглощения:

```text
alpha_avg < 0.20  → Sabine
alpha_avg >= 0.20 → Eyring
```

## Оценочная разборчивость речи

Дополнительно рассчитывается оценочная разборчивость речи:

```text
PerceivedClarity = DirectSignalFactor * SourceArticleFactor * RT60Factor
```

где:

- `DirectSignalFactor` — нормированная оценка уровня прямого сигнала;
- `SourceArticleFactor` — коэффициент артикуляции источника;
- `RT60Factor` — коэффициент соответствия RT60 рекомендуемому диапазону для выбранного типа помещения.

Этот показатель не является стандартным STI. Он используется как внутренняя оценка прототипа, которая помогает связать RT60, расстояние, уровень сигнала и артикуляцию в один более понятный результат.

## Типы помещений

В приложении используются типы помещений, для которых задаются рекомендуемые диапазоны RT60:

- лекционная аудитория;
- переговорная;
- студия;
- жилое помещение.

Тип помещения используется при формировании рекомендации и расчёте `RT60Factor`.

## Формат координат

Координаты источника и приёмника задаются в формате трёхмерной точки:

```text
(x; y; z)
```

Пример:

```text
(2.0; 1.5; 1.6)
```

Перед запуском анализа программа проверяет, что координаты можно разобрать и что они находятся внутри выбранного помещения.

## Запуск проекта

### Требования

- .NET SDK 8.0 или новее;
- Windows 10/11 или Linux;
- Visual Studio 2022, JetBrains Rider или другой редактор с поддержкой .NET.

### Запуск через командную строку

```bash
cd AcousticVision
 dotnet restore
 dotnet run
```

### Запуск через Visual Studio

1. Открыть проект `AcousticVision.csproj`.
2. Дождаться восстановления NuGet-пакетов.
3. Запустить проект кнопкой `Start`.

При первом запуске приложение создаёт локальную базу данных `acousticvision.db` и заполняет её начальными данными.

## Сборка

Для сборки проекта:

```bash
cd AcousticVision
 dotnet build
```

Для публикации в Release-конфигурации:

```bash
cd AcousticVision
 dotnet publish -c Release
```

## Начальные данные

При первом запуске в базу добавляются демонстрационные данные:

- типовые материалы: бетон, кирпич, стекло, дерево, штукатурка, ковролин, минеральная вата, акустическая панель и др.;
- фактуры: гладкая, шероховатая, пористая, перфорированная;
- источники звука: речь, мужской голос; тестовый тон;
- приёмники: слушатель, микрофон;
- несколько типовых помещений;
- поверхности для первого помещения;
- тестовая модель для проверки анализа.

## Основной workflow

1. Открыть раздел **«Помещения»** и создать помещение.
2. Проверить или добавить материалы в разделе **«Материалы»**.
3. Проверить или добавить фактуры в разделе **«Фактуры»**.
4. В разделе **«Поверхности помещения»** назначить материал и фактуру всем обязательным поверхностям.
5. Создать источник в разделе **«Источники»**.
6. Создать приёмник в разделе **«Приёмники»**.
7. В разделе **«Тест-модели»** выбрать помещение, источник и приёмник, задать координаты и метод анализа.
8. Открыть раздел **«Анализ»**, выбрать тестовую модель и выполнить расчёт.
9. Просмотреть результат, визуализацию и рекомендацию.
10. При необходимости открыть или распечатать отчёт.

## Ограничения текущей версии

- используется прямоугольная модель помещения;
- поверхности задаются фиксированным набором позиций;
- не учитывается частотная зависимость коэффициентов звукопоглощения;
- не моделируются отражения высокого порядка;
- не реализована трассировка лучей;
- не рассчитывается стандартный STI;
- мебель, занавески и люди не являются отдельными геометрическими объектами;
- оценочная разборчивость является внутренним показателем прототипа.
